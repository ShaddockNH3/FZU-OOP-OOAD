# 设计说明

原版能跑，问题在结构上。重构先列问题，再说怎么改的和付了什么代价。

## 原版的问题

| 位置 | 现象 |
| --- | --- |
| `GameEvent.apply(game: any)` | 事件要什么就给整个 `game`，`any` 把类型全放跑了，事件和 Game 互相咬死 |
| `EventParser.parseAction` | 十几层 `includes` 判断串成一个函数，加一种动作要改三处 |
| `Team.score` 与 `Team.teamStats.points` | 两套比分各写各的，罚球走一条路、比分回填走另一条，最后对不上 |
| `Game` 上的五个 `onXxx?` 回调 | 取消不了，重新 load 时容易和旧的回调串台 |
| `Game.seekToEvent` | 只重建球队、不重建时钟，回退后节次和统计不同步 |
| `Renderer` 732 行 | 画球场、造精灵、写球飞行动画、造飘字全在一个类里，还叠着 `requestAnimationFrame` 和 `setTimeout` |
| `index.html` 493 行 | 一半是内联 CSS，界面只能靠 `getElementById` 拼字符串改 |

## 现在怎么分

```
ui/  ──────────►  application/  ──────────►  domain/
 │                     ▲
 └───── app/ ────►  infrastructure/ ────────┘
```

- `domain` 只有规则：统计值对象、球员、球队、时钟、事件子类、`Match` 聚合。不认识 Vue、不认识 Pixi、不读文件。
- `application` 只有用例：把文字变成事件、装配比赛、按节拍播放、把状态摊平成读模型。依赖通过 `ports.ts` 里的接口进来。
- `infrastructure` 是适配器：xlsx 读取、浏览器计时器。换数据源只动这里。
- `ui` 是 Vue 组件和 Pixi 渲染器，允许依赖所有层。
- `app/container.ts` 是唯一 new 具体实现的地方。

`tests/architecture.test.ts` 用正则扫 import 卡住方向，改坏了会红。

## 几个关键决定

**播放用"重放到第 n 条"，不是增量回滚。** 任意时刻的状态 = 从零应用前 n 条事件。600 条事件重放一次是毫秒级，换来跳转、回退、重置共用同一段代码，不会出现"拖完进度条比分对不上"。

**文字解析做成规则表。** 每条规则只管一件事，顺序即优先级。两个坑靠顺序挡住：`犯规: 投篮犯规` 含"投篮"但没有命中/不中，投篮规则不会抢；`(2 罚球出手)` 含"罚球"，同理。

**比分以表格为准，个人得分靠累加。** 表格每行都有官方比分，`ScoreEvent` 直接覆盖球队得分。括号里的数字是该球员本场累计分，不是这一球的分值 —— 原版把它当分值用，球员得分会虚高。

**动画是可取消的补间。** 每个动画返回 `{ done, cancel }`，新事件进来先取消上一段（4 倍速下事件间隔比动画时长还短）。飘字和横幅这类不等结果的补间单独登记，取消时一起停，避免往已销毁的 Pixi 对象上写属性。

**事件类型靠 `instanceof` 分派。** 没把渲染逻辑塞进领域事件，也没用 `kind` + `as` 强转。

## 代价

- 领域实体和读模型各一套类型，改一个字段要动两处。
- 事件基类多了一个 `init` 对象参数，子类构造函数比原来啰嗦。
- 重放式 seek 在事件数上万时会变慢，现在 600 条无所谓。
- Pixi 和 Naive UI 让包体到 1.3 MB，没做分割。

## 对应课设的设计模式

| 模式 | 落在哪 |
| --- | --- |
| 抽象类 + 多态 | `GameEvent` 与 13 个子类的 `apply` |
| 工厂 | `EventFactory` + 规则表 |
| 观察者 | `Emitter`，引擎发快照，界面订阅 |
| 策略 | 每条解析规则是一份策略；`CourtRenderer` 是渲染策略接口 |
| 适配器 | `XlsxMatchSource`、`BrowserScheduler` |
| 组合 | `Match` 持有两队与事件流，`Team` 持有球员 |
